## Current user flow

```text
Launch Airlock
    → load and validate airlock_settings.json
    → preview friendly application names and running status
    → click End Workday
    → refresh the preview
    → confirm friendly application names and exact PIDs
    → show Ending Workday… and disable both buttons
    → request WM_CLOSE on a background worker
    → wait up to five seconds
    → force-terminate survivors
    → return results through a thread-safe queue
    → show Workday Ended ✓ or restore End Workday on failure
```

Refresh Preview restores `End Workday` after completion only when another
configured target is found running.

## Process-safety state

Matching is exact dictionary membership after `casefold()`. For example,
`Discord.exe` does not match `DiscordHelper.exe`, `DiscordUpdater.exe`, or any
other similar name.

Safety fixes completed today include:

- an explicitly injected empty process iterator no longer falls through to real
  host-process enumeration;
- the stored `ProcessMatch.pid` must equal the psutil object's PID;
- `psutil.Process.is_running()` verifies PID plus creation-time identity before
  any `WM_CLOSE` request;
- exited, reused, inconsistent, or unverifiable process identities are skipped;
- only configured and previewed process objects reach closure;
- psutil performs another PID-reuse check before Windows force termination.

The detailed review is in `docs/PROCESS_MATCHING_SAFETY_REVIEW.md`.

## Known limitations and risks

1. Survivors are automatically force-terminated after only five seconds.
2. A save prompt still open after the grace period can lose data.
3. WhatsApp is disabled because it showed an error after forced shutdown.
4. Processes without a top-level window go directly to forced fallback.
5. Differently named helper processes may remain running or relaunch.
6. The settings file is resolved from the current working directory.
7. There is no settings editor in the GUI.
8. The native `WM_CLOSE` wrapper is tested through injection, not against a real
   application in the automated suite.
9. Closing Airlock itself does not explicitly cancel an active daemon worker.
10. The packaged executable is unsigned and may trigger Windows warnings.
11. The custom application icon has not been implemented.
12. Current changes are uncommitted and unpushed.
